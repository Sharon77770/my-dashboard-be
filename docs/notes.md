# 메모장

앱 목록 → **메모장**에서 조직·프로젝트별 문서를 작성한다. Notion 방식의 블록 편집 인터페이스이며 독립적인 개인용 메모장이다. Notion 계정 연동이나 협업 서버는 사용하지 않는다.

## 프리랜서 사용 흐름

1. **＋ 폴더**로 조직명 폴더를 만든다.
2. 조직 폴더를 열고 **＋ 하위 폴더**로 프로젝트명 폴더를 만든다.
3. **＋ 새 문서**에서 제목, 저장할 폴더와 템플릿을 선택한다.
4. 문서의 제목을 직접 수정하고 본문에서 `/`로 블록을 추가한다. 블록 핸들로 이동·중첩하고, 텍스트 선택 도구 모음에서 굵게·기울임·밑줄·취소선·링크·색상을 지정한다.
5. 체크리스트를 완료 표시하고 표의 행·열을 편집한다. 이미지 블록의 업로드 또는 이미지 붙여넣기/드롭으로 사진을 첨부한다.
6. 입력이 멈춘 뒤 1초 후 자동 저장한다. **저장** 또는 Ctrl/Cmd+S로도 저장할 수 있다.
7. 왼쪽 검색에서 폴더 경로·문서 제목을 찾는다. 항목의 **⋯**에서 이름·이모지·상위 폴더를 변경한다.

지원 블록: 본문, 제목, 글머리/번호 목록, 체크리스트, 접기 목록, 인용문, 코드, 구분선, 이미지, 표. Markdown 입력 단축 구문과 가져오기/내보내기를 지원한다. 편집 도구 모음과 블록 메뉴는 한국어다. 모바일에서는 문서 상단 목록 버튼으로 폴더 탐색기를 펼친다.

## 템플릿

| 템플릿 | 초기 구성 |
| --- | --- |
| 빈 문서 | 비어 있는 페이지 |
| 할 일 | 오늘/이번 주 체크리스트와 완료 기록 |
| 업무 기록 | 오늘 한 일, 진행 중인 일, 문제와 해결, 다음 할 일 |
| 가계부 | 날짜·분류·항목·수입·지출·메모 표, 월간 수입/지출/잔액 정리 |
| 프로젝트 개요 | 고객·기간·담당자, 목표·범위, 일정 표, 산출물 체크리스트 |
| 회의록 | 일시·참석자, 안건, 결정 사항, 후속 작업 |
| 주간 회고 | 완료한 일, 좋았던 점, 개선점, 다음 주 계획 |
| 아이디어 노트 | 아이디어, 참고 자료, 실험할 일 |

각 문서는 템플릿의 독립 복사본이다. 가계부는 자유롭게 편집하는 문서 템플릿이며 수입·지출 합계와 잔액은 직접 입력한다. 빈 템플릿이 기본 선택이다.

## 저장·충돌·삭제

문서·폴더 메타데이터, 블록 JSON과 첨부 이미지는 기존 SQLite DB에 저장되어 dashboard-data 백업에 포함된다. 에디터와 템플릿 라이브러리는 같은 서버의 정적 파일로 제공하며 런타임 CDN이나 외부 에디터 서비스에 문서를 전송하지 않는다. 외부 HTTPS 이미지 URL을 사용하면 사용자 브라우저가 해당 주소에 직접 접근한다.

저장은 revision을 비교하고 성공 시 증가시킨다. 제목 변경 후 본문 저장은 순차 요청이며 각각 버전을 검사한다. 다른 창에서 변경한 문서를 덮어쓰지 않는다. 실패하면 현재 편집 내용을 유지하고 화면 전환을 중단한다. Markdown 내보내기로 보관한 뒤 새로고침 버튼으로 최신 문서를 다시 열 수 있다. 앱 전환 시 편집 버퍼와 진행 중인 자동 저장은 유지하며, 새로고침·탭 닫기에는 미저장 내용이 있으면 브라우저 확인을 요청한다. 페이지 강제 종료나 네트워크 단절 시 아직 서버에 저장되지 않은 내용의 복구는 보장하지 않는다.

삭제는 확인 후 영구 삭제한다. 문서의 첨부 이미지도 함께 삭제된다. 비어 있지 않은 폴더는 삭제를 거부하므로 먼저 하위 항목을 이동·삭제해야 한다. 이미지 블록만 지우면 이미지 데이터는 문서 삭제 전까지 유지한다. 실패/취소된 편집 과정에서 이미 업로드한 이미지도 이 규칙을 따른다.

문서 최대 2 MiB / 2,000개 블록, 블록 중첩 16단계, 폴더·문서 총 5,000개, 상위 폴더 체인 32단계. 첨부는 파일별 10 MiB 이하 PNG/JPEG/GIF/WebP만 허용하며 SVG/HTML은 거부한다. 모든 API와 이미지 읽기는 OWNER 세션을 요구하고 변경 요청에는 CSRF를 적용한다. 이미지의 원래 파일명·서버 경로를 저장하지 않는다.

Markdown 가져오기는 현재 본문 교체를 확인한 뒤 실행한다. Markdown은 색상·복잡한 표·접기 상태 등 모든 블록 속성을 보존하는 백업 형식이 아니다. 내보낸 첨부 URL은 로그인된 원래 대시보드에서만 접근할 수 있으며 이미지 바이너리를 `.md`에 포함하지 않는다.

## 구현과 검증

`notes/controller → notes/service → notes/repository → SQLite` 구조다. `NoteContentValidator`가 문서 크기·블록 종류·URL을 검증한다. 폴더 관계·순환 이동·revision·이미지 형식은 `NoteService`가 검증한다. 프런트 `notes.js`는 탐색/폼/저장 흐름, `notes-templates.js`는 초기 블록, `tools/notes-editor/editor.jsx`는 BlockNote 브리지를 담당한다.

- `NotesIntegrationTest`: 계층·권한·CSRF·충돌·첨부 검증.
- `node tools/launcher/notes-test.cjs`: UI 폴더 탐색·템플릿·비동기 저장 보호.
- `cd tools/notes-editor && npm ci --ignore-scripts && npm run build && npm test`: 실제 BlockNote 렌더링·템플릿·Markdown 테스트.
- 기존 launcher/theme/responsive 검사 및 Maven `verify`.

DOM 테스트는 실제 브라우저 레이아웃·터치·파일 선택기 검증을 대체하지 않는다.
