# 장비 실시간 로그

앱 목록의 **장비 로그**, 또는 장비 카드의 **로그**에서 장비 → Docker/tmux → 대상을 선택하고 **실시간 보기**를 누른다. 기본 서버(local)와 등록 SSH 장비 모두 지원한다. Tailscale 장비는 저장된 네트워크 설정을 그대로 사용한다.

- Docker: 전체 컨테이너 목록에서 선택한다. `docker logs --follow --tail 200 --timestamps`로 stdout/stderr를 읽는다. 중지된 컨테이너는 기존 출력을 읽고 종료한다. Docker 데몬과 로그를 읽을 수 있는 계정 권한 및 로그 드라이버가 필요하다. 원격 장비의 Docker 설정을 사용하며 별도 권한을 부여하지 않는다. 기본 Compose는 호스트 Docker 소켓을 연결하지 않으므로 local의 호스트 컨테이너 조회에는 Docker 접근 환경이 별도로 필요하다.
- tmux: 접속 계정의 기본 tmux 소켓에 있는 모든 세션·창·pane을 선택한다. `capture-pane -p -J -S -500`으로 최근 화면/스크롤백을 1초마다 읽는다. 변경 시 화면을 교체한다. attach/키 입력/pipe-pane을 사용하지 않는다. 종료된 pane의 출력 보존이나 다른 계정·별도 이름 소켓은 지원하지 않는다.
- 서버 이미지는 tmux를 포함한다. SSH 장비에는 해당 CLI가 설치되어 있어야 한다. 누락 시 설치 필요 오류를 표시한다.
- **중지**, 대상 변경, 앱 이동 시 수신을 취소한다. 브라우저 종료 시 취소를 시도하며 전달 실패 시 서버의 최대 15분 제한으로 정리한다. 컨테이너/tmux 세션 자체는 종료하지 않는다.
- 자동 스크롤을 해제하면 위쪽 출력을 읽을 수 있다. 화면 지우기는 표시만 지우며 원본 로그는 바꾸지 않는다. tmux는 다음 화면 변경 때 전체 스냅샷을 다시 표시한다.

기존 Studio 작업 전송을 재사용한다. 400ms 간격으로 HTTP 세션 소유 작업을 조회하며 Docker 출력은 약 100ms 단위로 최대 16KiB를 읽는다. 서버는 작업당 최근 150개 이벤트/약 200,000자를 보유하고 브라우저는 최근 200,000자를 표시한다. 느린 수신으로 append 이벤트가 빠지면 생략 안내를 표시한다. 영구 로그 저장소가 아니다. Studio와 합쳐 최대 4개 실행 작업, 최대 15분 연결, 완료 작업 30분 보존 제한을 적용한다.

전용 `studio/logs.py` 어댑터는 고정 인자 배열만 실행하고 Docker 전체 ID(64자리 소문자 hex), tmux pane ID(%숫자)를 검증한다. 목록/캡처는 10초, 2MiB 제한이다. 프로젝트 루트를 검증하되 읽기 전용 조회는 IDE 프로젝트 잠금을 잡지 않는다. 로그 내용은 인증된 사용자에게 그대로 제공되므로 UI는 textContent로만 표시하고 DB나 애플리케이션 로그에 복제하지 않는다.

검증: `python3 -m unittest discover -s src/test/python -v`, Maven `verify`, `node tools/launcher/logs-test.cjs`(기존 UI 검사와 같은 jsdom 환경).

CLI 동작 참고: [Docker logs 공식 문서](https://docs.docker.com/reference/cli/docker/container/logs/), [tmux 공식 문서](https://github.com/tmux/tmux/wiki/Advanced-Use).

## 표시 옵션

로그 화면의 **보기**에서 원문 / JSON 정렬(자동 인식)을 선택한다. JSON 객체·배열과 줄별 JSON(JSONL), Docker 타임스탬프 뒤의 JSON을 들여쓰며 JSON이 아닌 줄이나 수신 중 미완성 JSON은 원문으로 남긴다. 완전한 여러 줄 JSON 한 문서도 지원한다. 각 줄마다 접두사가 붙은 여러 줄 JSON은 합쳐 해석하지 않는다. 숫자·문자열 표기를 그대로 유지하므로 큰 숫자 ID도 반올림하지 않는다.

**컬러맵**은 구문 강조(키·문자열·숫자·참/거짓/null), 로그 수준(ERROR/FATAL, WARN 등), 단색 중 선택한다. **줄바꿈**과 **코드 블록**으로 가로 스크롤 및 배경/테두리 표시를 바꿀 수 있다. 밝은/어두운 테마의 기존 의미별 색상을 따른다.

옵션은 현재 브라우저의 계정별 `workspace-log-view-v1:<account>` 설정에만 저장하며 로그 본문은 저장하지 않는다. 표시 옵션을 바꿔도 연결과 수신 버퍼는 유지되고 원문으로 되돌릴 수 있다. 표현 변경은 브라우저에서 수행하며 장비 CLI/API/DB 계약은 변경하지 않는다. 강조는 textContent 기반 span으로 렌더링하며 원본 HTML을 실행하지 않는다. 들여쓰기는 64단계/표시 400,000자 제한을 넘으면 원문을 표시하고 구문 색상 노드는 6,000개까지 적용한 뒤 나머지는 단색으로 표시한다. 새 내용이나 옵션 변경이 없으면 다시 렌더링하지 않는다.
