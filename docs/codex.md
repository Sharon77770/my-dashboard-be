# IDE Codex 패널

상단 **설정 · 사용량**에서 모델·추론 강도, 직접 승인(`user`), 나 대신 승인(`auto_review`), 승인 요청 안 함(`never`)과 실행 범위(`read-only` / `workspace-write` / `danger-full-access`)를 선택한다. 나 대신 승인은 `on-request`로 필요한 추가 권한을 자동 심사하며 거절된 요청은 실행되지 않는다. **승인 요청 안 함**은 명령 승인을 끄며, 전체 접근은 SSH 사용자 권한으로 폴더 밖 파일과 네트워크까지 실행한다. 기본값은 읽기 전용·직접 승인이다. 설정 패널은 화면 일부만 차지하고 내부에서 스크롤한다. 설정은 IDE의 장비·작업 폴더별 `sessionStorage`에 유지하고 새 대상에는 기본값을 적용한다. 실행 중 설정 조회·닫기는 가능하지만 변경은 작업 완료 후 가능하다. 기존 대화의 다음 요청에도 현재 선택한 권한을 적용한다.

설정 화면은 계정의 기간별 잔여 사용률·초기화 시각과 현재 대화의 누적/입력/캐시 입력/출력 토큰·컨텍스트 잔여량을 제공한다. 계정 한도는 연결·새로고침·완료된 대화 후와 수동 요청 시 갱신한다. 조회 실패나 미제공은 표시하되 대화 기능을 막지 않는다. 남은 계정 한도를 토큰 수로 환산하지 않는다. 사용량/계정정보는 브라우저에 영속 저장하지 않고 토큰 이벤트가 없는 복원 대화는 대기로 표시한다. [장비 Codex](device-codex.md)도 같은 설정·사용량 UI를 공유하며 AI 비서는 별도 정책을 유지한다.

채팅 패널의 기본 폭은 480px이며 분할선으로 넓힐 수 있다(최대 설정값 960px, 화면 여유 폭 이내). 이전 기본값 320px은 480px로 갱신한다. 패널 상단 **대화 확대**는 에디터·탐색기 DOM을 유지한 채 Codex가 작업 영역을 채우게 하며 **분할 화면**으로 복원한다. Files/Editor/Git으로 전환해도 확대를 해제한다. 본문은 14px, 입력창은 기본 46px 높이에서 필요할 때 화면 높이의 25% 이내로 늘린다.

전송 직후 사용자 말풍선 하나를 먼저 표시하고 서버의 첫 사용자 item을 받으면 같은 행을 서버 ID에 연결한다. 이후 같은 ID 이벤트는 행을 갱신한다. CLI 준비 중 연속 전송과 추가 지시 전송은 각각 중복 실행을 막는다. 서버가 수신을 확인하기 전 실패한 임시 행은 지우고 입력을 복원하되 새로 작성한 입력은 덮어쓰지 않는다. 실제로 다시 전송한 다른 ID의 메시지는 내용이 같아도 유지한다. 이 처리 경로는 장비 Codex도 공유한다.

장비 자체 관리에는 별도 [장비 Codex](device-codex.md)를 사용한다. SSH 장비별 CLI 준비, 분리된 로그인·대화, 작업 폴더와 승인 흐름을 제공한다.

패널 상단의 `SSH Codex`에 선택한 SSH 환경의 로그인 이메일과 요금제를 표시한다. 서버 AI 비서는 사이드바와 설정의 `서버 Codex`에 별도 계정을 표시한다. `account/read` 공개 정보만 사용하며 API 키 인증/이메일 없는 계정은 이메일 미제공으로 표시한다. 로그인 후 재조회하고 로그아웃·폴더 변경 시 이전 표시를 지운다. 이메일은 브라우저 저장소에 저장하지 않는다. 계약: [공식 App Server](https://learn.chatgpt.com/docs/app-server).

명령 시작 이벤트의 `aggregatedOutput=null`은 아직 출력이 없는 정상 상태다. 브리지는 빈 출력으로 변환하고 `item/commandExecution/outputDelta`를 스트리밍한다. 명령 승인과 최종 thread 복원이 계속 진행된다. 실패 turn은 IDE와 서버 비서 모두 FAILED job이며 인증 만료(401), 샌드박스 오류(502), 기타 모델 실패(502)를 구분한다.

대시보드 AI 비서의 Workspace Memory는 비공개 MCP 검색·조회 기능을 제공한다. 서버 비서는 turn 시작 전에 관련 항목만 제한된 크기로 검색한다. IDE Codex의 별도 job·인증 경계는 유지한다. [Workspace Memory](workspace-memory.md).

프로젝트 작업은 IDE에서 SSH 장비의 폴더를 열고 **Codex** 탭을 사용한다. 프로젝트 Codex CLI, 인증, 세션은 선택한 원격 SSH 계정에서 관리한다. 서버 전역 assistant는 홈·Dock·모든 앱·검색의 **AI 비서** 내장 앱으로 열고 Linux 대시보드 서버의 Codex CLI와 인증을 사용한다. 두 기능은 job 경로와 MCP 권한이 분리되어 있다. 로그인은 기기 코드 로그인을 이용한다.

- 모델/추론: 설치된 CLI의 model/list를 조회해 선택한다. 고정 모델 이름을 사용하지 않는다.
- 세션: 상단 시계 버튼에서 검색·복원하고 ＋로 새 대화를 시작한다. 보관된 세션을 선택하면 보관 해제 후 연다. 메뉴에서 이름 변경·분기·보관·컨텍스트 압축을 실행한다.
- 컨텍스트: 현재 파일, 선택 영역, 프로젝트 상대 경로, 2 MB 이하 이미지, 활성 CLI 스킬을 첨부한다. 첨부 칩의 ×로 제거한다. 선택 영역은 CodeMirror에서 선택한 내용이다. 파일 전송 전 미저장 편집은 저장해야 한다.
- 실행: 읽기·분석 또는 파일 수정 허용을 선택하고 Enter로 전송한다. Shift Enter는 줄바꿈이다. 다음 요청은 같은 thread에 이어진다. 실행 중 입력하면 turn/steer로 추가 지시를 보낸다.
- 승인: 명령/파일 변경 요청은 한 번 허용·세션 동안 허용·거절을 선택한다. 질문은 패널에서 답변한다. 중지는 turn/interrupt이며 하단 실행 중지는 job 강제 종료다. 이미 변경된 파일은 유지된다.
- 결과: 응답, 실행 명령과 출력, 파일 diff, 계획, 토큰 사용량을 표시한다. 코드 블록을 복사할 수 있다. 변경 사항 리뷰는 CLI review/start로 미커밋 변경을 검사한다. 모델 응답 HTML은 실행하지 않는다.
- `/help`, `/new`, `/history`, `/compact` 명령을 지원한다. 메뉴에서 CLI에 등록된 MCP 연결 인증 상태를 확인할 수 있다.

대시보드 자체 Codex는 IDE 패널과 별도의 반응형 대화 창을 사용한다. 페이지·등록 앱 열기와 일정·메모·GitHub의 조회·작성·수정·삭제를 다루며 IDE 파일·스킬 컨텍스트와 프로젝트 도구를 제공하지 않는다. 일정·메모의 영구 삭제는 대화에서 대상을 확인하고 GitHub 위험 작업은 대시보드 브라우저 승인을 거친다. 모델과 추론 강도는 대시보드 assistant 전용 화면에서 선택한다. [AI 비서와 MCP 도구](assistant.md).

서버 assistant의 도구 준비는 Codex CLI 최신 stable 릴리스를 자동 확인한다. 확인 결과는 10분간 캐시하고, 업데이트가 적용되면 이어지는 model/list 조회에 새 모델과 지원 reasoning effort가 표시된다. GitHub 릴리스 확인이 실패하면 현재 설치 버전을 계속 쓴다. 이 자동 업데이트는 대시보드 서버에만 적용되며 프로젝트 편집기의 SSH Codex는 대상 서버에 설치된 버전을 유지한다.

새 세션은 첫 메시지 전에는 화면의 draft다. 첫 turn부터 선택한 SSH 계정의 Codex 저장소에 저장한다. 화면에는 최근 50 turn을 표시한다. 마지막 대화 되돌리기는 thread/rollback으로 마지막 turn의 기록을 제거하며 파일을 되돌리지 않는다.

## 구현 범위와 차이

공식 [IDE 기능](https://learn.chatgpt.com/docs/codex/ide)과 [App Server](https://learn.chatgpt.com/docs/app-server)를 참고한 독립 웹 클라이언트다. VS Code 확장 바이너리/화면을 그대로 임베드한 것은 아니다. 현재 설치된 Codex App Server의 model/list 응답을 사용하며 고정 모델 이름과 추론 강도 목록을 두지 않는다.

VS Code 전용 명령, OpenAI 클라우드 작업 위임, 확장 전용 UI 설정, 네이티브 Plan collaboration mode, 마켓플레이스 설치·OAuth 관리, 임의 permission/MCP elicitation UI는 포함하지 않는다. 마지막 종류의 미지원 서버 요청은 승인하지 않고 오류 응답으로 종료한다. reasoning은 공개 summary만 표시하며 내부 content는 보내지 않는다. API 키 직접 입력 UI와 SSH 사용자 OS 권한 상승은 제공하지 않는다.

## 검증

Docker 빌드에서 Python 파일/Git 경계와 오프라인 App Server fixture 테스트를 실행하고 Maven verify를 수행한다. fixture는 모델 조회, thread 소유 폴더 검사, 승인 거절, 실제 stdin/stdout 프레임과 완료 기록을 검증한다. 외부 로그인이나 유료 모델 호출 없이 실행한다.

실제 설치 CLI에서는 모델 목록·세션 목록·계정 상태와 빈 thread의 수명을 확인했다. 실제 외부 계정 로그인과 유료 응답 성공은 검증하지 않았다. UI는 jsdom/CodeMirror와 반응형 CSS 규칙으로 검증하며 브라우저 화면 캡처 검증과는 구분한다.

## 편집 공간 중심 배치

IDE 상단은 실행 대상 선택, 폴더 메뉴, 패널 전환을 한 줄로 표시한다. 폴더 경로 입력과 열기는 폴더 메뉴에서 수행하며, 연결 후 메뉴를 닫고 남은 앱 높이를 에디터가 채운다. 작업 결과는 하단 접이식 상태 영역이며 로그나 Git diff가 발생하면 열린다. Codex 헤더에는 현재 세션과 목록·새 세션·메뉴·설정 및 사용량을 두고, 입력창 아래에는 첨부와 전송을 배치한다. 모델·추론·권한 선택과 상세 사용량은 설정 화면에 둔다.

폴더 메뉴의 경로 필드는 선택한 장비의 `list` 결과를 HTML 자동완성 목록으로 사용한다. Codex 패널은 VS Code 확장의 작업 흐름을 기준으로 세션·컨텍스트·승인·스트리밍·리뷰를 같은 작업 공간 안에서 제공하지만, 설치된 Codex CLI와 App Server가 제공하지 않는 기능은 임의로 흉내 내지 않는다.

다크모드 가독성: 모델·추론·권한·실행 대상 선택창은 불투명한 테마 배경과 명시적인 글자·경계 색을 사용한다. 펼친 네이티브 option/optgroup에도 테마 색을 적용하고, 비활성 컨트롤은 전체 투명도를 낮추지 않는다. 모델 선택 글자는 12px, 권한·사용량 안내는 11px로 표시한다.
