# Workspace Memory

AI 비서의 여러 대화가 공유하는 짧은 장기 컨텍스트다. Notes는 긴 문서, Calendar는 확정 일정이다. 가능성·계획은 Memory에 `TENTATIVE`로 남기며 확정 일정으로 말하지 않는다.

## 생성과 대화

사용자가 명시적으로 기억을 요청하거나 비서의 저장 제안을 승인했을 때만 생성한다. 전체 대화 자동 추출은 없다. `sourceThreadId`는 출처이며 소유권이 아니다. 스레드 삭제는 Memory를 삭제하지 않는다. 정확히 같은 활성 기억은 중복 저장 대신 강화한다. 충돌하는 새 사실은 이전 항목을 보관하고 `supersededBy`로 연결한다.

## 검색과 Context Composer

SQLite의 제한된 텍스트·metadata 검색 결과를 범위, 일치도, 확정도, 중요도로 정렬한다. 각 turn은 최대 8개·2,400자의 관련 기억만 받는다. 전체 테이블을 prompt에 넣지 않는다. 후보 검색만으로 사용 횟수는 증가하지 않고 실제 컨텍스트 포함 또는 직접 조회에서 증가한다. 내용은 `UNTRUSTED DATA`로 표시되어 명령으로 취급하지 않는다. 검색 실패 시 일반 비서 대화는 계속된다.

## Lifecycle

매일 03:00 서버 시간에 결정적 정리를 수행한다. 가능성·미확정·후속 작업은 설정된 보존일에 `STALE`, 그 뒤 7일에 `ARCHIVED`로 이동한다. 임시 유형의 ISO 날짜·시각 힌트는 만료 시각으로 해석하며 지난 항목은 `EXPIRED`로 표시하고 7일 후 보관한다. 보관 항목은 설정된 기간 후 삭제된다. 직접 만든 항목 보호가 켜져 있으면 자동 삭제하지 않는다. Pin 항목은 항상 자동 삭제에서 제외한다. 조회만으로 확정도를 올리지 않는다. 설정은 비서 설정의 Memory 관리에서 변경한다.

## 승격과 보안

확정 일정 또는 문서로 발전하면 사용자 승인 후 기존 `PlannerService` 또는 `NoteService`로 생성하고 원본을 `PROMOTED`로 연결한다. 중복 승격은 기존 대상 ID를 반환한다. Service 범위는 실제 Service ID를 검증한다. REST는 OWNER 세션·CSRF, MCP는 비공개 bearer 인증을 적용한다. 비밀번호·토큰·키 형태의 내용은 저장을 거절한다. Memory 내용은 로그나 전체 대화 아카이브로 복제하지 않는다.
