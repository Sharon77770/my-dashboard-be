# 병역 캘린더

앱 라이브러리의 **병역 캘린더** 또는 기존 **캘린더 → 병역 캘린더**에서 연다. 최초에 이름, 복무 유형, 입대·소집일을 등록한다. 단일 OWNER의 개인 복무 정보 하나를 SQLite에 저장한다.

## 제공 기능

- 서버 시각을 기준으로 복무율, 복무 일차, 전역·소집해제 D-day와 남은 시간을 표시한다. 열린 화면의 수치는 매초 갱신한다.
- 입대, 사용자가 등록한 일병·상병·병장 진급, 전역을 타임라인과 월간 달력에 표시한다.
- 휴가·훈련·당직·기타 일정을 등록하고 날짜별로 조회·수정·삭제한다. 휴가 예산, 사용, 예정, 잔여 일수를 함께 보여 준다.
- 캘린더 연동을 켜면 기존 캘린더와 오늘 일정 위젯에도 `[병역]` 일정이 나타난다. 해당 항목을 누르면 병역 캘린더에서 원본을 편집한다. 별도의 일반 일정 복사본은 만들지 않는다.
- 다른 탭에서 수정하면 WebSocket 알림으로 두 캘린더를 갱신한다. 월·선택 날짜·열린 안내·작성 중인 폼을 유지한다. 충돌한 저장은 초안을 보존하고 오류를 표시한다.

## 날짜와 휴가 계산 기준

| 유형 | 기본 복무 개월 |
| --- | --- |
| 육군 / 해병대 | 18 |
| 해군 | 20 |
| 공군 / 사회복무요원 | 21 |
| 직접 설정 | 실제 종료일 필수 |

기본 기간은 2022년 이후 입대에만 적용한다. 이전 복무는 실제 전역·소집해제일을 입력한다. 앱의 예상 종료일은 입대일에 복무 개월을 더한 날짜의 전날이며, 해당 일이 없는 달은 그 달 마지막 날이다. 예: 2026-01-01 육군 → 2027-06-30, 2024-08-31 육군 → 2026-02-28. 이는 앱의 예상 계산으로 실제 인사 명령을 대신하지 않는다. 복무 연장·단축 등을 반영하려면 실제 통보받은 종료일로 덮어쓴다.

진급일은 실제 통보받은 날짜를 직접 등록한다. 최소 진급 소요기간으로 자동 확정하지 않는다. 날짜는 입대일 이후, 전역일 이내의 계급 순서여야 한다. 사회복무·직접 설정에는 병 계급 진급일을 사용하지 않는다.

모든 날짜는 `Asia/Seoul` 기준이다. 복무율 구간은 **입대일 00:00 이상, 전역일 다음 날 00:00 미만**이다. 전역 당일은 D-day이며 당일까지 복무 중으로 표시하고 다음 날 100%·복무 완료가 된다. 복무 일차는 입대 당일 1일차, 경과 일수는 완료한 날짜 수, 남은 일수는 오늘을 포함한 복무 날짜 수다. 서버 시각과 브라우저 단조 증가 시계를 사용하고 서울 자정에 집계를 다시 조회한다.

일정의 시작·종료일은 모두 포함한다. 휴가 차감일수 미입력 시 전체 날짜 수를 사용하며 실제 차감일수(0 포함)로 조정할 수 있다. 시작한 휴가는 전체 차감일수를 사용에, 미래 휴가는 예정에 집계한다. 잔여는 `예산 - 사용 - 예정`이며 음수면 초과로 표시한다. 예산 미입력 시 잔여도 미설정이다. 휴가끼리 날짜 중복은 거부한다. 일정은 복무기간 안에 최대 366일, 전체 1,000개까지 허용한다.

프로필 삭제는 병역 일정도 함께 삭제한다. 일반 캘린더 일정은 유지한다. 연동 해제는 병역 원본을 남기고 일반 캘린더에서만 숨긴다. 복무기간을 줄여 기존 일정이 범위 밖으로 나가면 먼저 일정을 수정하도록 안내한다.

## 검증

`MilitaryDatesTest`는 월말·윤년·서울 자정·전역 당일 경계를, `MilitaryIntegrationTest`는 권한·CSRF·저장·revision 충돌·휴가 중복·집계·캘린더 투영·삭제 경계를 검증한다. `WorkspaceEventsTest`는 병역 변경의 두 캘린더 무효화를 확인한다. `tools/launcher/military-test.cjs`는 실제 앱 JS와 mock API로 진입·매초 표시·부분 갱신·초안 보존·캘린더 이동·지연 응답 역전을 검증한다. 실제 브라우저 렌더링·모바일 터치는 별도 확인 대상이다.
