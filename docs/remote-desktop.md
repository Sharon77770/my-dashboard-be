# 원격 데스크톱

앱 라이브러리의 **원격 데스크톱**에서 장비를 선택한다. 미설정 장비도 모두 표시한다. 장비가 없다면 **장비 추가**로 SSH 주소·계정·비밀번호를 등록한다. 장비 추가 메뉴의 **원격 데스크톱**, 검색의 REMOTE 실행도 동일한 연결 도우미를 거친다.

## 연결 흐름

1. **장비 확인**은 읽기 전용이다. 기존 RDP/VNC 설정 또는 Linux 도구·설치 권한을 확인하고 필요한 작업을 설명한다.
2. 기존 설정은 **연결하기**, 미설정 Linux는 **화면 준비 및 연결** 또는 **설치하고 연결**을 누른다. 설치 동작은 이 버튼을 누른 뒤에만 시작한다.
3. **장비 확인 → 도구 준비 → 화면 시작 → 연결 확인** 단계와 현재 안내를 표시한다. 준비에는 최대 12분이 걸릴 수 있다.
4. 실제 guacd 인증·핸드셰이크가 성공하면 자동으로 원격 화면을 연다. 새 자동 연결 프로필은 검증 후 저장하고 기존 SSH 호스트 키·네트워크·점프 경로를 유지한다.

창을 닫아도 서버의 준비 작업은 계속된다. 같은 장비를 다시 선택하면 진행 중 작업을 따라가며 완료 후 연결한다. 실패하면 비밀번호/연결 설정을 수정하거나 다시 확인·재시도한다. 비율을 추측한 진행률은 표시하지 않는다.

## 지원 환경

| 환경 | 동작 |
| --- | --- |
| 기존 RDP/VNC | 기존 화면·인증정보를 변경하지 않고 연결 확인. 실패 시 도우미의 연결 설정에서 프로토콜·포트·계정·비밀번호만 수정 |
| Debian/Ubuntu apt | root, 비밀번호 없는 sudo, 또는 사용자가 이번 설치용으로 입력한 sudo 비밀번호로 자동 설치 |
| Linux에 필수 도구가 이미 있음 | 설치 없이 가상 화면을 시작하거나 재사용 |
| Windows | 원격 데스크톱을 지원하는 에디션에서 원격 접속을 허용한 뒤 RDP(기본 3389) 계정 정보를 입력. PIN 대신 계정 비밀번호 사용. OS의 RDP 정책·방화벽은 자동 변경하지 않음 |
| macOS | 시스템 화면 공유·접근 권한을 직접 허용한 후 VNC(기본 5900) 정보를 입력 |
| 기타 Linux/제한 OS | 필요한 조치를 안내하며 임의 설치·보안 설정 변경 없음 |

새 Linux 설치는 TigerVNC, XFCE 데스크톱, 파일 관리자, 터미널, 한글 폰트를 준비한다. 패키지는 python3, tigervnc-standalone-server, tigervnc-tools, openbox, xterm, xfonts-base, xfce4, dbus-x11, fonts-noto-cjk다. 배포판의 인증된 apt 저장소를 사용한다. 기존 Openbox 환경은 유지하고, 새 XFCE 환경은 전용 D-Bus 세션으로 시작한다. 실제 모니터의 로그인 화면·Wayland 세션과는 다른 **가상 데스크톱**이다.

sudo 비밀번호는 필요한 경우에만 별도로 입력받아 SSH stdin으로 전송하고 설치 프로세스에만 사용한다. 저장된 SSH 비밀번호를 암묵적으로 재사용하지 않는다. API 응답·로그·명령 인자·디스크에 보관하지 않고 입력창은 전송·닫기 시 비운다. sudoers나 시스템 로그인 정책을 변경하지 않는다. 설치 실패 시 이미 설치된 패키지를 자동 제거하지 않는다.

## 화면 조작

원격 화면에는 다시 연결·키보드·전체 화면을 표시하고, 화면 맞춤/원본 크기·클립보드·Ctrl+Alt+Del·연결 도우미는 메뉴에 둔다. 한 손가락은 포인터 이동, 탭은 클릭, 두 손가락은 스크롤이다. 키보드 입력창은 한글을 Unicode 키 입력으로 전송하며 Enter/Tab/삭제/Esc를 제공한다. 원격 Ctrl+K·Alt+Left가 대시보드 단축키로 처리되지 않도록 분리한다.

화면 맞춤은 실제 가용 공간과 원격 해상도를 반영한다. 최소 원격 폭은 640px이며 모바일에서는 전체 화면을 축소한다. 원본 크기는 화면 내부 스크롤로 이동한다. RDP/VNC 서버가 크기 변경을 지원하지 않아도 축소 맞춤은 유지한다. 전체 화면 지원은 접속 브라우저에 따른다.

## 보존·포트·수명

기존 VNC 서비스(5900–5919에서 RFB 확인)가 있으면 비밀번호를 재설정하지 않고 기존 연결 등록을 안내한다. 새 화면은 비어 있는 5920–5999와 X 디스플레이 20–99를 선택하며 기존 프로세스·X 잠금 파일을 삭제하지 않는다. 자동 VNC는 loopback에만 바인딩하고 저장된 SSH 호스트 키·계정·점프 경로를 통해 터널링한다. 원격 방화벽 포트를 열 필요가 없으며 SSH TCP forwarding은 허용되어야 한다. guacd와 백엔드는 기본 Compose처럼 네트워크 네임스페이스를 공유해야 한다. 수동 등록 RDP/VNC는 기존 직접 접속 경로를 사용한다.

대상 `~/.personal-dashboard-desktop`에 계정 전용 잠금·프로세스 상태·VNC 비밀번호 파일을 둔다. 백엔드의 `data/remote-desktops`에는 암호화한 관리 정보를 저장한다. SSH 대상 신원이 달라지면 이전 관리 정보를 사용하지 않는다. 같은 계정의 중복 설치는 파일 잠금으로 막고, 같은 장비의 중복 API 요청은 진행 중 작업을 반환한다. 동시 작업은 최대 4개, 최근 상태는 최대 64개다.

탭을 닫아도 대상 데스크톱은 유지된다. 대상 재부팅 후 **연결하기**로 관리 중인 화면을 다시 준비할 수 있다. 자동 부팅 서비스는 설치하지 않는다. 백엔드 재시작으로 메모리 작업 상태가 사라져도 관리 정보는 유지된다. DB 스키마 변경은 없다.

## 검증

- Java: OWNER/CSRF·입력 검증, 읽기 전용 사전 확인, 다른 설정·점프 경로 보존, 접속 검증 실패 시 프로필 유지.
- Python: 포트 충돌, 패키지 설치 생략, sudo 비밀번호 stdin 전달과 인증 실패 시 설치 차단.
- UI: `tools/launcher/remote-setup-test.cjs`는 jsdom을 사용해 사전 확인·재시도·비밀번호 지움·기본 포트·자동 연결을 검사한다.
- 실제 연결: `scripts/check-remote-desktop-live.mjs`는 격리 SSH 장비(`scripts/fixtures/remote-desktop` 이미지), 대시보드, guacd를 필요로 한다. `REMOTE_TEST_URL` 기본값은 localhost:18190, `REMOTE_TEST_ENV` 기본값은 `.tools/remote-fixture.env`이며 테스트 계정 DASHBOARD_AUTH_ID/PASSWORD와 REMOTE_TEST_PASSWORD만 사용한다. 기존 운영 프로필을 사용하지 않는다.
