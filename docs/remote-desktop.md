# 원격 데스크톱 자동 구성

장비 카드 → **원격 자동 연결** → **자동 구성 및 연결**을 누른다. 기존 VNC/RDP 프로필이 있으면 실제 guacd 연결을 먼저 검증하고 원격 탭을 연다. 실패 시 기존 서비스나 비밀번호를 변경하지 않고 주소·포트·인증정보 확인을 안내한다.

원격 화면이 미사용인 SSH 장비는 별도의 Linux 가상 데스크톱을 구성한다. 이는 대상 장비에서 실행되며 실제 모니터의 로그인 화면·Wayland 화면을 공유하지 않는다. 드라이브/NAS 저장 위치와 무관하다. 로컬 백엔드 기본 장비는 설치 대상에서 제외한다.

## 지원 환경

| 환경 | 처리 |
| --- | --- |
| 설정된 VNC/RDP | OS에 관계없이 기존 연결 검증 후 재사용. 기존 인증정보 필요 |
| Debian/Ubuntu + apt | SSH 계정이 root 또는 비대화형 sudo 가능하면 부족한 패키지를 설치 |
| Linux에 도구가 이미 있음 | Python 3, Xtigervnc/Xvnc, tigervncpasswd/vncpasswd, Openbox, xterm 재사용 |
| 기타 Linux | 도구가 부족하면 자동 설치를 중단하고 관리자 설치 안내 |
| macOS | 자동 변경 없이 화면 공유·접근 승인 및 기존 VNC 등록 안내 |
| Windows/기타 SSH 셸 | 자동 설치를 중단하고 VNC 또는 지원 에디션 RDP 구성 안내 |
| 모바일·제한 OS | SSH와 호환 원격 서버가 없으면 자동 구성 불가 |

설치 패키지는 python3, tigervnc-standalone-server, tigervnc-tools, openbox, xterm, xfonts-base다. 패키지 관리자의 인증된 저장소를 사용하며 임의 설치 URL을 실행하지 않는다. sudo 비밀번호를 재사용하거나 대화형 승인을 자동 우회하지 않는다. apt 잠금은 최대 30초 대기하며 설치 실패는 저장소 접근·권한·디스크 확인을 안내한다. 설치 완료된 패키지는 실패 시 자동 제거하지 않는다.

## 포트·기존 설치·수명

실행 중인 기존 VNC(5900–5919에서 RFB 확인)를 발견하면 비밀번호를 바꾸지 않고 기존 설정 등록을 안내한다. 다른 포트의 기존 VNC는 장비 설정에 명시하면 우선 재사용한다. 새 가상 화면은 5920–5999 중 사용 가능한 포트와 X 디스플레이 20–99를 선택한다. TCP 점유·X 잠금·X 소켓을 검사하고 시작 경쟁 시 최대 3번 시도한다. 기존 프로세스를 종료하거나 잠금 파일을 지우지 않는다.

생성된 VNC는 loopback에서만 수신한다. 백엔드가 등록된 SSH 계정·호스트 키·Tailscale 네트워크 옵션을 사용해 터널을 열고, 같은 네트워크 네임스페이스의 guacd가 임시 loopback 포트로 접속한다. 터널 종료 시 SSH와 임시 리스너를 닫는다. guacd를 별도 호스트에 배포한 경우 이 경로는 사용할 수 없으며 기본 Compose 네트워크 공유 구성이 필요하다. 대상 SSH 서버에서 TCP forwarding을 허용해야 한다.

VNC 비밀번호는 서버에서 생성한 8자리 임의 영숫자이며 자격증명 보관소로 암호화한다. 대상에는 VNC 전용 비밀번호 파일만 계정 전용 디렉터리에 기록하고 명령 인자·API·작업 메시지로 전달하지 않는다. VNC 포맷 자체는 강력한 비밀 저장 방식이 아니므로 대상 계정 권한과 SSH 전송이 보호 경계다. [TigerVNC 비밀번호](https://tigervnc.org/doc/vncpasswd.html), [Xvnc 옵션](https://tigervnc.org/doc/Xvnc.html).

대상 `~/.personal-dashboard-desktop`에 잠금·프로세스 상태·비밀번호를 저장한다. 동일 계정의 중복 설치는 파일 잠금으로 차단한다. 관리 중인 프로세스와 VNC 응답을 확인해 재사용한다. 백엔드는 `./data/remote-desktops`(기본 Docker `/app/data/remote-desktops`)에 암호화된 연결 상태를 보존한다. 장비 호스트·SSH 포트·계정·키가 변경되면 이전 상태를 사용하지 않는다.

원격 화면은 탭을 닫아도 계속 실행된다. 대상 재부팅 또는 세션 정리 정책으로 프로세스가 종료되면 **원격 자동 연결**을 다시 눌러 시작한다. OS 부팅 서비스나 사용자 자동 로그인은 설치하지 않는다. 기존 물리 화면 서비스, 방화벽, 시스템 로그인 정책은 자동 변경하지 않는다.

## 상태와 검증

작업은 IDLE → RUNNING → READY/BLOCKED다. READY는 VNC 생성뿐 아니라 guacd 인증·핸드셰이크까지 성공한 상태이며 UI가 원격 탭을 연다. BLOCKED는 필요한 조치를 표시하고 재시도를 허용한다. 장비별 중복 요청은 실행 중 작업을 반환하며 최대 4개 동시 작업, 64개 최근 상태를 메모리에 둔다. 백엔드 재시작 후 작업 상태는 사라지지만 설치·암호화된 연결 정보는 유지된다. 설치 SSH 연결은 최대 12분으로 제한한다. 창을 닫으면 상태 조회와 자동 탭 열기를 중지하며 서버 작업은 계속된다.

단위 테스트로 기존 설정 보존, 설치 생략, OS 안내, 포트·디스플레이 충돌을 검증한다. 격리 SSH Debian 장비에서 실제 패키지 설치, 점유 포트 회피, 재실행 재사용, SSH 터널, guacd 인증과 WebSocket 스트림을 검증한다. 실제 Windows/macOS의 원격 서버 설정 및 물리 모니터 공유는 검증 범위가 아니다.
