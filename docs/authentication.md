# 외부 서비스 인증과 검증

대시보드 로그인과 외부 서비스 로그인은 별개다. 외부 인증은 공식 CLI 또는 환경변수/토큰 주입을 우선 사용한다. 브라우저 로그인만 제공하는 서비스는 서버의 원격 화면에서 사용자가 직접 인증한다. 비공식 로그인 API 호출, CAPTCHA/2단계 인증 우회, ID/비밀번호를 명령줄 인자로 받는 로그인 자동화는 구현하지 않는다.

| 서비스 | 현재 실행/인증 방법 | 인증 상태 저장 |
| --- | --- | --- |
| Tailscale | `.env`의 `TAILSCALE_AUTHKEY`로 자동 인증. 키가 없을 때만 `docker compose exec tailscale tailscale login`의 안내 URL 사용 | `tailscale-state` 볼륨, Java 앱에 키 전달 안 함 |
| 카카오톡 | Wine에서 공식 PC 설치 프로그램을 자동 설치/실행. 공식 CLI 로그인 수단이 확인되지 않아 앱 로그인 화면에서 직접 입력 | `wine-profile` 볼륨 내 Wine 사용자 프로필 |
| GitHub / Git | 코드 에디터의 GitHub 로그인 → 원격 gh 기기 코드 인증 → Git credential helper 연결. 다른 호스팅은 원격 Git 인증 설정 재사용 | 선택한 서버 계정(로컬/SSH)의 GitHub CLI/credential helper 저장소 |
| Codex | 코드 에디터의 기기 코드 로그인 → 원격 `codex login --device-auth`. 원격 CLI 환경변수/API 키 방식도 사용 가능 | 선택한 서버 계정(로컬/SSH)의 Codex 인증 저장소. Java/SQLite에 복사하지 않음 |

CLI에서 카카오톡 실행/재실행은 `docker compose exec -d wine launch-kakao`로 한다. 계정 입력 화면은 대시보드의 **카카오톡**에서 연다. 대시보드의 브라우저 위치 설정과 관계없이 Wine은 서버에서 실행된다. 카카오톡 계정 비밀번호를 받는 별도 API나 환경변수는 두지 않는다.

Tailscale의 키는 시작 스크립트가 권한 600의 임시 파일로 전달하고 시도 후 삭제한다. 인증이 30초 이내에 끝나지 않거나 거부되어도 데몬과 공유 네트워크는 유지하므로 카카오톡과 로컬 기능을 사용할 수 있다. `.env`나 실행 중 컨테이너 설정에 주입한 키 자체가 자동 삭제되는 것은 아니다.

## 검증 기준

- 실제 계정 로그인 성공은 자동 검증 목표에 포함하지 않는다. 외부 서비스의 로그인 화면 또는 CLI 인증 진입점이 존재하는지 먼저 확인한다.
- 화면에 계정/비밀번호를 요구하면 존재하지 않는 테스트 ID와 임의 비밀번호로 한 번 요청하여 실패 안내를 확인한다. CLI가 인증 키를 받는다면 임의의 잘못된 키로 거부를 확인한다.
- Tailscale 검증은 실제 tailnet 상태 볼륨과 분리된 임시 컨테이너에서 수행한다. 서비스 장애/timeout은 인증 거부 성공으로 간주하지 않는다.
- 실제 메시지 발송, 연락처 접근, 저장소 쓰기, 유료 API 호출은 로그인 검증에 포함하지 않는다. Git·Codex 구현 시에도 이 기준을 적용한다.
- 자격증명·인증 URL·토큰 전체·사용자 대화 내용은 로그, 테스트 산출물, 문서에 남기지 않는다. 결과에는 화면 존재 여부와 실패 유형만 기록한다.
- Wine에서의 로그인 화면 검증은 실제 계정의 정상 로그인·메시지 송수신·통화·업데이트 호환성을 보장하지 않는다. 서비스가 공식 지원하지 않는 실행 환경에서는 버전 변경에 따라 동작이 달라질 수 있다.

## 확인한 결과 (2026-09-14)

| 대상 | 결과 |
| --- | --- |
| Tailscale 1.102.3 | 격리된 컨테이너의 임의 키를 `invalid key: unable to validate API key`로 거부. 거부 후에도 데몬 유지/재시작 0회, 임시 키 파일 삭제 확인 |
| 카카오톡 26.7.1.5263 / Wine 11.0 | 한글 로그인 화면과 입력 확인. 임의 ID/비밀번호 제출 후 `카카오계정 또는 비밀번호를 다시 확인해 주세요.` 표시. 테스트 입력 제거 |
| 대시보드 연결 | OWNER 로그인 후 DESKTOP/kakaotalk 세션 생성, 실제 VNC 화면 전달, 세션 종료 확인. CLIENT 브라우저 설정에서도 서버 화면을 사용하는 DOM 동작 검사 통과 |
| GitHub CLI 2.100.0 / Codex 0.154.0 | Linux SSH fixture에 공식 CLI 자동 설치. 양쪽 기기 인증 URL/코드의 웹 전달과 취소 확인. 격리된 임시 인증 환경의 임의 키로 각각 HTTP401 거부 확인. 실제 계정 로그인/유료 응답 미실행 |

카카오톡 화면은 네이티브 X11 및 VNC 캡처로 검사했다. 이 결과에 실제 계정의 로그인 성공, 메시지 전송, 연락처 조회는 포함하지 않는다.

남은 Wine 호환성 제한: 일부 팝업을 연 뒤 배경의 로고/입력 컨트롤이 다시 그려지지 않는 현상이 관찰됐다. 로그인 실패 안내는 읽을 수 있었으나 모든 카카오톡 화면의 정상 렌더링을 보장하지 않는다. 창을 다시 열거나 `docker compose restart wine`으로 앱을 재시작할 수 있다.
